# Файл предметов

Каталог: `resources/items.json`. После редактирования перезапустите игру.
В нём находятся 12 существующих предметов. Каждый вызов создания предмета
даёт отдельный экземпляр; объединения в стопки нет.

| Поле | Значение |
| --- | --- |
| `id` | Уникальный постоянный ID для ссылок из кода |
| `name` | Название в игре |
| `description` | Описание; пустая строка, если ещё не задано |
| `weight_kg` | Вес всего предмета в кг; `null`, если неизвестен |
| `price` | Базовая цена в кредитах; `null` запрещает торговлю |
| `quantity` | Число использований; `null`, если неприменимо |
| `width`, `height` | Целые размеры в клетках, не меньше 1 |
| `category` | Категория, например `хлам`, `инструменты`, `еда`; пока пустая строка |
| `texture_path` | Путь `res://...` к изображению; пустая строка — простая фигура |
| `properties` | Объект свойств; `{}`, если свойств нет |
| `slot_type` | Только для деталей: `wheel`, `engine`, `transmission` |
| `model` | Только для деталей: название модели |

Вес и цена относятся к предмету целиком, а не к одной единице содержимого.
При расходовании содержимого они пока не меняются. Цена выкупа по-прежнему
зависит от общего коэффициента торговли и состояния детали.

## Свойства

| Ключ | Пример | Эффект |
| --- | --- | --- |
| `fatigue_restore` | `5` | При использовании +5 к бодрости (показателю усталости) |
| `satiety_restore` | `40` | При использовании +40 к сытости |
| `water_restore` | `50` | При использовании +50 к запасу воды |
| `speed_bonus_percent` | `20` | Установленный двигатель даёт +20% скорости |

Значения неотрицательны. Свойства восстановления требуют `quantity` не
меньше 1. Каждое использование расходует одну единицу, применяет все
указанные эффекты восстановления и удаляет предмет после исчерпания.
Восстановление ограничено максимумами показателей. Пункт «Использовать»
определяется свойствами, поэтому переименование сигарет не ломает действие.

`speed_bonus_percent` поддерживается только для двигателя. Он действует
после установки и не расходует количество. Неизвестные свойства считаются
ошибкой: новые типы эффектов нужно сначала поддержать в коде.

## Пример существующего предмета

```json
{
  "id": "cigarettes",
  "name": "Сигареты",
  "description": "",
  "weight_kg": null,
  "price": 20,
  "quantity": 21,
  "properties": {"fatigue_restore": 5},
  "texture_path": "",
  "category": "",
  "width": 1,
  "height": 1
}
```

Чтобы описать новый предмет, скопируйте объект в массив `items`, задайте
новый ID и заполните поля. Между объектами нужны запятые; комментарии
в JSON не поддерживаются. Добавление записи только описывает предмет:
оно не добавляет его автоматически в магазин, заказы или события.
Ассортимент будет настраиваться отдельно.

Текущий код использует ID `cigarettes`, `upgraded_engine`, `test_crate`,
`test_box`, `test_long_cargo`, `test_small_item` и `standard_` с ID места
установки детали. Эти ID не переименовывайте без обновления ссылок.
Установочные размеры пока фиксированы: колёса 2×2, двигатель и трансмиссия
2×3. Изменённый размер детали может сделать её несовместимой с машиной.

Описание отображается в карточке; заданная текстура заменяет простую фигуру
в карточке. Рисование предметов внутри сетки пока остаётся прежним.
Категория хранится в данных, фильтров категорий пока нет. Изображения нужно
импортировать в Godot, прежде чем проверять их в игре.

Ошибочные определения и дубли ID выводятся в журнал Godot и пропускаются.
Отсутствующий обязательный предмет заказа не создаёт пустой заказ;
ошибочная стартовая деталь оставляет незаполненное место в автомобиле.
JSON включён в настройки экспорта.

Цены и бонус конкретного двигателя теперь редактируются здесь; прежние
`upgraded_engine_price_credits` и `upgraded_engine_speed_multiplier` удалены
из настроек баланса. Общие коэффициенты топлива, ремонта, износа и выкупа
остаются в `GameBalanceSettings.tres`.
